# Generative UI Ideas

The goal is to move beyond simple text/markdown responses and allow the AI to render rich, interactive UI components directly in the chat stream.

## Concept

The AI will provide a JSON response (or a specific markdown block) that describes *what* to render and the *data* to render it with. The client (NativeChat) will interpret this description and render the corresponding native GPUI component.

## Protocol

We can use a specific "tool use" or "structured output" format, or simply a fenced code block with a specific language tag, e.g., `json:ui`.

### Example Response

```json
{
  "type": "ui",
  "component": "weather-widget",
  "data": {
    "location": "San Francisco, CA",
    "temperature": 72,
    "condition": "Sunny",
    "forecast": [
      { "day": "Mon", "temp": 70 },
      { "day": "Tue", "temp": 68 }
    ]
  }
}
```

## Architecture

1.  **Registry**: We need a registry of "renderable components" on the client side.
    *   `WeatherWidget`
    *   `StockChart`
    *   `KanbanBoard`
    *   `CodeEditor` (embedded)
    *   `Map`

2.  **Parser**: The chat rendering logic needs to detect these structured blocks.
    *   If a message contains a `json:ui` block, parse it.
    *   Look up the `component` type in the registry.
    *   Deserialize the `data` into the component's props.

3.  **Renderer**:
    *   Instead of just `Markdown::new(content)`, the message renderer will produce a list of elements: `[Markdown(text_part_1), WeatherWidget(data), Markdown(text_part_2)]`.

## Future Possibilities

*   **Interactive Elements**: The rendered UI should be interactive (buttons, sliders). Actions taken on the UI could send new messages back to the AI (e.g., "User clicked 'Refresh' on WeatherWidget").
*   **Dynamic Layouts**: The JSON could describe a layout (VFlex, HFlex) of primitive components (Text, Image, Button) rather than just pre-baked widgets, allowing for "Server-Driven UI" generated by AI.
*   **Sandboxing**: If we allow arbitrary code execution (e.g., React-like components defined in JS/WASM), we need a sandbox. For now, a fixed set of native Rust components is safer and more performant.
